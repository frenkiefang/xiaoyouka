# Supabase visit tracking setup

This repository contains the table migration and Edge Function for recording a
name shown with `?name=`. It records at most once per browser, per name, every
30 minutes. The timestamp is generated by PostgreSQL, not by the visitor.

## Deploy

1. Install and authenticate the Supabase CLI, then link this repository to the
   intended Supabase project.
2. Replace `YOUR_PROJECT_REF` in `tracking-config.js` with that project's
   reference ID. This is a public function URL, not a secret.
3. Deploy the migration and function:

   ```powershell
   supabase db push
   supabase functions deploy record-name-visit
   supabase secrets set ALLOWED_ORIGIN=https://xiaoyouka.fffxc.xyz
   ```

4. Publish `tracking-config.js` and `index.html` with the rest of the static
   site.

## Check the result

Open `https://xiaoyouka.fffxc.xyz/?name=张三`, then use the Supabase SQL Editor:

```sql
select name, page_path, visited_at
from public.name_visits
order by visited_at desc;
```

Refreshing the same browser URL within 30 minutes must not add a row. Opening
another name, another browser, or returning after 30 minutes creates a row.

## Security model

`name_visits` has RLS enabled and grants are revoked from `anon` and
`authenticated`, so visitors cannot read the collected names or insert data
directly through the data API. The Edge Function accepts requests only from
`https://xiaoyouka.fffxc.xyz`; it writes through a server-only service-role key.
